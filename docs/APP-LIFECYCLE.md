# 应用运行管理

工具箱沿用应用卡片原有的单个操作按钮：未运行显示「开始」；运行时显示「运行中」，鼠标悬停或键盘聚焦变为「结束运行」。点击请求正常退出，观察到进程离开后才回到「开始」。启动／退出中的按钮暂不可重复操作。

可见主页每 2.5 秒刷新，失焦返回也刷新。不把启动请求等同于已运行；符合识别条件但无法读取时显示状态未知。清单可设置 `lifecycle.detection`：默认 `process` 适合电脑信息等后台常驻工具；`window` 要求登记路径的进程拥有可见的顶层主窗口（最小化仍算可见）。隐藏启动器、渲染／GPU／网络辅助进程不单独构成窗口模式的运行状态。

黄狗风云采用 `window`：其游戏关闭后隐藏启动器仍可能驻留，主页此时恢复「开始」，再次点击按原启动入口唤起客户端自身的单实例逻辑。不修改黄狗风云代码，不清理或强杀它的隐藏进程。电脑信息等内置工具继续按 `process` 识别，托盘／浮窗驻留仍显示运行。重复启动运行中的应用优先恢复已有窗口。

`AppControl.exe` 接收服务端固定应用清单的路径，使用完整映像路径、当前 Windows 会话和窗口所属 PID 校验；前端不提交任意 PID／路径。不按文件名终止进程、不使用 taskkill、不强杀。开发更新留下的同目录、同工具名、带数字版本号的 previous 文件仅对内置工具识别，避免正在运行的旧版本被误认为未运行。

内置工具通过注册的 Windows 消息请求退出，绕过关闭到托盘，同时保留原生关闭事件和已有保存逻辑。工作箱退出不会连带关闭其他独立工具。图片／房间的保存失败或取消不会被强制跳过。外部软件使用窗口关闭消息，能否退出取决于软件自身行为；无主窗口或权限不足时不假装关闭成功。

「正在退出」最长观察 15 秒，仍存在则恢复运行状态，用户可处理应用中的保存提示。ShareX 是工作箱内嵌组件，不被当成独立进程强行结束。旧版工具缺少统一退出协议时，运行状态仍可显示，按钮提示从托盘退出并重新打开更新版本。

本轮原生更新仅替换开发目录 exe，不关闭用户当前窗口；锁定的旧映像在同目录保留备份。首次使用新行为需从托盘退出并重新打开工作箱及相应工具。

验证用自己创建的隐藏 WinForms 测试进程，涵盖后台识别、同名不同路径、取消关闭、正常退出；没有对用户运行中的黄狗风云或象棋执行测试关闭。
