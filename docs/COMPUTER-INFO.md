# 小羊电脑信息

从工作箱应用列表打开，或运行 `desktop-dev/小羊电脑信息.exe`。登录、深浅色、字体与窗口大小沿用工作箱规范。程序与工作箱共用开发目录，移动时保留整个目录。

## 使用

- 仪表盘：CPU、内存、GPU 占用及最近 60 个采样；网卡接收／发送速率、磁盘读写、磁盘可用容量、硬件名称与系统运行时间。
- 「硬件详情」支持每个逻辑处理器的独立曲线、按编号／负载排序，核心／线程／缓存信息；显卡独立读数与驱动；内存条插槽／容量／型号／配置速率；每块物理磁盘读写、活动率、队列和分区容量；每个网卡的链路速率、地址、累计流量；主板／BIOS 与可用电池传感器。
- LibreHardwareMonitor 0.9.6 传感器每 3 秒更新。展开设备查看当前值及保留采样内最低／最高值，点击项目名看曲线。分域功耗仅作独立读数，不能全部相加。
- 「功率估算」显示插座侧估算功率、曲线、近期平均／最高及构成。优先使用 CPU Package 和每张独显整体功耗，不重复叠加 Core／集显分项。缺失时使用总负载和可调空闲／满载参数；加上其他部件预留值后除以电源效率。参数按账号保存。
- 初始 CPU 15–150 W、GPU 15–250 W、其他 50 W、效率 90% 均为通用假设，非自动识别额定值；多 CPU／GPU 参数填写合计。无独显时 GPU 两项设为 0。参考范围采用传感器项 ±10%、模型项 ±50%、效率 ±5 个百分点，是敏感性范围而非置信区间。不包含显示器和外接独立供电设备，准确功率需要插座功率计校准。
- 默认 `Ctrl + Alt + R` 显示／隐藏悬浮窗。可在「悬浮窗」页录制组合键，选择显示方式、初始位置、不透明度后保存。支持 `Alt + R`；如果被 NVIDIA 等程序占用，会提示冲突并保留原快捷键。
- 「小窗」可拖动，右键打开仪表盘或隐藏。「简洁叠加」固定在选定屏幕角落，不抢焦点、不拦截鼠标。当前显示 CPU／GPU／内存占用及网卡上下行。
- 默认关闭仪表盘后驻留托盘，快捷键仍然有效；取消「关闭主窗口后保留在托盘」则关闭即退出。托盘菜单「退出」始终彻底退出、关闭悬浮窗并释放快捷键。
- 注销后隐藏悬浮窗、释放快捷键；再次登录后恢复账号保存的配置。启动时不会自动显示悬浮窗，也没有开机自启动。

## 采样口径

| 项目 | 来源与口径 |
| --- | --- |
| CPU | PDH `Processor Information(*)` 的 `% Processor Time`，保留 group/index 标识，排除 `_Total` 分组。总占用优先 PDH 总计，单处理器组才回退 GetSystemTimes。多组编号有测试，超过 64 线程的实机未验收。 |
| 内存 | `GlobalMemoryStatusEx` 的物理总量与可用量之差。容量显示采用 1024 进制。 |
| GPU | Windows PDH GPU 引擎计数器，同一引擎跨进程求和，再取最繁忙引擎，避免多个引擎直接相加超过 100%。 |
| 温度／显存／功耗 | NVML 提供 NVIDIA 基础数据，LHM 补充各厂商支持的传感器；详情按设备独立显示。首页最繁忙 GPU 引擎与首张 NVIDIA 卡温度可能属于不同设备。 |
| 网络 | 网卡实际收发字节差／实际间隔，反映当前使用量，不进行测速。默认最活跃物理网卡，也可选择单独的物理或虚拟网卡，不把 VPN 与物理网卡流量叠加。拔除手动选择的网卡后显示缺失。 |
| 磁盘 | PDH 全部及各物理盘读写字节／秒，活动率为 100% 减去 Idle Time，限制在 0–100%；同时显示当前队列长度。卷容量每 30 个采样更新。型号按物理盘编号关联，不以分区数量推断物理盘数量。 |

驱动不支持、计数器缺失、权限不足或尚未形成两个采样时显示「—」，不生成演示读数。数据来源不同，短时读数不保证与任务管理器、NVIDIA 叠加层完全一致。

没有 FPS、帧时间、风扇控制或超频。CPU 温度／功耗和主板风扇取决于设备、已安装的 PawnIO 驱动及权限；组件不会安装驱动或自动提权。LHM 无法读取 MSR 时的 CPU Power 初值 0 被当作不可用，未接入 EC 探针的 0°C 也不作为真实温度。悬浮层适用于桌面及普通窗口／无边框窗口，不使用游戏注入，不保证覆盖独占全屏或受保护桌面。

## 资源与生命周期

`ComputerProbe.exe` 是常驻的只读 .NET Framework 采集进程，约每秒输出一条 NDJSON。仪表盘与悬浮窗共用服务内的一个采集进程，只在需要显示数据时启动；停止请求约 6.5–7.5 秒后关闭。采样超时会终止组件并允许后续请求重试。程序正常退出、服务关闭、父进程退出或输入管道断开时回收组件。

仪表盘暂停、切换至设置、隐藏或最小化时停止页面请求；悬浮窗仍显示则继续采样。最近 60 个样本只在内存，不写持续日志或历史缓存；悬浮窗设置按账号保存在工作箱 SQLite。不会向公网传送硬件信息，不安装驱动，不修改硬件配置。

## 接入与构建

稳定 ID 为 `xiaoyang-computer`。应用清单按固定文件名自动发现内置程序，支持旧宿主未传入新增环境变量的情况。回到工作箱、主页可见时每 2.5 秒刷新，以及「刷新应用」按钮会重新读取清单和运行状态。已经运行的旧版服务必须先从托盘退出再重新打开，才能加载本轮修复。

`npm run computer:host` 编译电脑信息宿主与采集器；`npm run build` 构建共享界面和服务；`node scripts/update-app.mjs` 更新开发目录资源并保留备份。完整构建使用 `npm run desktop:build`，需先退出正在运行的开发版程序。没有生成安装包。

验证：`npm test`、`npm run test:computer`、`npm run test:native`、`npx tsx tests/computer-ui.ts` 和 `node tests/bundled-smoke.mjs`。浏览器桥接测试使用明确的测试替身，不等同于实际按键和原生拖动验收。

实现依据：[Windows 性能计数器](https://learn.microsoft.com/en-us/windows/win32/perfctrs/about-performance-counters)、[GetSystemTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes)、[GPU 引擎统计](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/)、[NVIDIA NVML](https://docs.nvidia.com/deploy/nvml-api/nvml-api-reference.html)。
