## 截图折叠同步修复（2026-10-03）

用户反馈原先固定等待 100 ms 会捕获最小化动画的中间帧。已移除此等待，加入 `CaptureWindowTransition`：临时禁用本窗口过渡、cloak、最小化、DwmFlush、解除 cloak 并再次等待桌面呈现，最后恢复原过渡设置；完成后才向 ShareX 发起截图。普通窗口、最大化窗口共用这一路径；已在托盘隐藏的窗口不会被意外显示。设置关闭折叠及图片编辑仍跳过此流程。

运行 `npm run test:capture-transition`，先显示测试窗口作为真实截图基线，再在准备完成的同一调用链立即通过 ShareX 全屏截图，统计原窗口特征色像素。普通／最大化窗口准备分别为 19／12 ms，截图中窗口残留像素均为 0；已最小化与托盘隐藏状态检查通过。记录：`runtime/capture-transition-3oaJVv/results.json`。这是本机样本，不作为所有显示器刷新率下的固定时间承诺。测试图片只在隔离项目目录保存。

原生同步依据：[DWM 窗口属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)、[DwmFlush](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmflush)。DwmFlush 只等待本调用进程已排队的呈现，不能单独视为所有系统动画结束，因此同时取消本窗口过渡并使用 cloak。

截图右键菜单已移除所有图标，恢复菜单与多选导出分支同样使用纯文字。工具栏和预览按钮保留原有图标。

修复后 TypeScript 检查、前端构建及 Windows exe 构建通过。在隔离图库中检查深色右键菜单，8 个操作均为纯文字且左对齐；验收图为 `runtime/screenshot-menu-text-only.png`。测试服务已关闭。
